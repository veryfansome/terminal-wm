CANDIDATE: head = r5_closure_routing_memory (new), genome = parent x partner crossover.

WHAT THE DATA FORCES (checked against evolve/jail_data/train_sample.jsonl, 24 real sequences)

Every mutating step in these trajectories carries a content-free observation. A move renders as
"cwd=/ exit=0\n" with an empty body, and so does every redirect op; within one sequence 9-14 of the
~30 steps share that one byte-identical observation string. So the observation channel says nothing
at all about where anything went. The entire routing signal lives in ONE frozen mean-pooled
embedding of the command string "mv <src> <dst>", and the model has to make the destination path
extracted from that string collide with the source path extracted from a later "mv <dst> <dst2>"
and with the query path of a later "cat <dst2>". That collision -- one shared path-identity space
that a first-position extractor and a second-position extractor both land in -- is the whole task.
The compositional reads are also visible in the data as exact observation duplicates under
different commands (e.g. step 14 "cat /tmp/w/cups/g53/f149.tmp" and step 22
"cat /tmp/w/cups/usr/share/misc/magic.txt.1" render identical text after two intervening moves),
and the content-free mutating steps separate cleanly from contentful ones by duplicate-cluster
size (9-14 vs 1-3). That is a label-free mining rule that works on this data as written.

WHAT THE MECHANISM IS

wrap() registers one module on the net (before the optimizer is built, so it is trained) and
re-points net.forward, holding the original bound method in a closure; the module never holds a
reference back to the net, so there is no parent-child cycle and .to(device) does not recurse.

Per sequence, from the command embeddings c_i alone:
  q_i = unit(path_key(gelu(src_in(c_i))))     source / query key
  k_i = unit(path_key(gelu(dst_in(c_i))))     destination / write key
  g_i = sigmoid(move_gate(gelu(ctl_in(c_i)))) transport gate
  (a_i, b_i) = softmax(mix_coef(...))         mixing coefficients on the 2-simplex
src_in and dst_in are initialised to the same weights plus small noise and share the final
projection path_key, which is what lets "the second path of command i" and "the only path of
command j" land on the same key.

Two causal attention matrices over the same write keys, both with a learned recency decay
-softplus(log_decay)*(i-j) and a LEARNED NULL COLUMN appended before the softmax and dropped after:
  A_src[i,j] = attn(q_i . k_j),   A_dst[i,j] = attn(k_i . k_j),   both strictly j < i.
The null column is what makes "nothing is at this path yet" representable: without it a softmax
over a single unrelated earlier step returns that step with weight 1. Rows with no admissible j
put all mass on null and read exactly zero, so no NaN and no spurious read.

Routing matrix and content register:
  M = g * (a * A_src + b * A_dst)                    strictly lower triangular
  U0 = (1 - g) * obs * live_obs
  V = sum_{p=0..hops} M^p U0                         computed by `hops` batched matmuls
  reads = A_src V
  contribution to the arch's prediction at command position i = rg_i * reads_i * out_scale
This is the Neumann series for V = M V + U0, i.e. the transitive closure of the routing graph.
A depth-d move chain is resolved by the d-th term of the series, in d matmuls, rather than by a
32-iteration python recurrence with an unnormalised outer-product memory. I verified the algebra by
hand-simulating it on a 6-step board with ideal keys: with commands
  cat A(=X) / cat P(=Y) / mv A B / mv B C / cat Q(=Z) / cat C
the read at the final step is exactly X, and the reads at the two moves are X as well.
a and b live on the 2-simplex because the correct content algebra is convex: a move is (1,0) and an
append "cat s >> acc" is a length-weighted mixture of the source content and what was already at
the destination, which in a mean-pooled embedding space is approximately a convex combination of
the two observation embeddings. Those append steps are ~40% of the ops in this data, and the r2
prior's single source read cannot express them at all.

WHAT NEITHER PARENT COMPUTES

Both programs run the same head, r18_transition_forwardmodel_consistency, which is a TRAIN-ONLY
auxiliary and is switched off entirely unless the arch exposes transition_from_emb; neither
program's arch is the r18 latent-transition arch. Neither program computes, at prediction time, a
path-addressed store of which content currently sits where. This candidate adds exactly that, and
keeps the parent head's principle -- a shared transition operator supervised label-free from
within-batch structure -- by supervising this router's operator the same way.

The train-time aux mines, with no labels, pairs (j < i) where obs_i duplicates obs_j (squared
distance under 3% of the sequence's mean pairwise distance) while cmd_i does NOT duplicate cmd_j,
and where both steps' duplicate clusters are small (<= max_dup), which excludes the content-free
mutating steps. Deeper mined reads (larger i - first matching j) are preferred when capping. The
read at i, and the arch's own prediction at i, are then trained with a multi-positive InfoNCE whose
logits are NEGATIVE SQUARED L2 over the sequence's other contentful observations -- the same
geometry the forced-foil measurement ranks in -- plus a small MSE anchor that keeps the read in the
raw observation scale it is being added in.

WHY THIS SHOULD MOVE comp_ca, WHICH IS A PAIRED DIFFERENCE

comp_ca cancels anything that keys on which location is being read: that read command is the same
token in both arms. This router's read at the scored position is A_src[scored, :] V, and V is a
function of the MOVE commands' source and destination keys. Role-swapping the chain re-encodes
those move commands, which changes k_j and q_j, which changes M, which changes V, which changes
what the read returns -- to the partner's content. So native_hit rises and swap_stayed falls, which
is the differential, rather than raising both arms together. A first-mover or move-order heuristic
cannot be expressed here: position enters only as a monotone recency decay shared by both arms.

THE EVAL-TIME GATE, EXPLICITLY

The scored position is a command whose own observation is withheld. Nothing in the read path is
gated on that observation. Row admissibility uses only live_cmd (the even/command slot), never
live_obs; live_obs only zeroes a step's OWN content contribution U0, and U0 at position i is read
only by positions after i, never by i itself. The gates rg and g, the coefficients a and b, and
both keys come from the command embedding alone -- never from the observation. So if the harness
pads, zeroes, or truncates the final observation, the read at the scored command is unchanged. The
computation is also strictly causal: reads_i depends only on {c_1..c_i} and {obs_1..obs_{i-1}}.

Nothing resolves the chain outside the model. The head never parses a command string, never looks
at a path, and has no access to text -- it sees only the frozen 768-d embeddings the harness
already feeds the trunk, and every key, gate and coefficient is a learned function of them trained
by gradient descent. The mined aux uses observation duplicates only to CHOOSE which steps to
supervise and as the contrastive target, never as an input.

THE CROSSOVER

The two programs differ in objective, arch, target and batcher. I keep the parent's arch
(r4_fingerprint_conditioned_composition), its transport-chain batcher with its parameters, its
target (identity -- required, because the routed content is injected in raw observation space and a
retargeted prediction space would misalign the injection), and the optim and stream both programs
share. From the partner I take r22_exact_target_equivalence_quotient as the objective: it is the
partner's one mechanism that is loss-level and therefore arch-agnostic, and it is the one that
matches this head, because the routed content at a post-move read is byte-identical to an earlier
exposure's target, so a loss that treats exactly-equal targets as one equivalence class is the
right pressure for a router whose output is precisely a previously-seen observation.

HOW IT FAILS

1. The frozen mean-pooled encoder may not linearly separate "first path" from "second path" in a
   two-path command. If src_in and dst_in cannot pull the two paths apart, q and k collapse onto
   each other, A_src and A_dst become the same matrix, and the router degenerates to a
   recency-weighted average of prior contents. Then out_scale stays near zero and the candidate
   scores like its parent rather than below it -- but it will not beat it.
2. The mined supervision covers exposure/re-read duplicates. If most such pairs in the training
   split are depth-0 re-reads rather than post-move reads, the router can satisfy the aux with a
   plain "same path, no moves" lookup and never learn the transport gate. The span-preferring cap
   is meant to counter this; if it does not, comp_ca will not move even with a healthy aux curve.
3. Cost: routing adds hops+3 batched matmuls of [B,n,n] x [B,n,768] per forward. At B=64, n<=32
   that is roughly a tenth of the trunk's cost, so the fixed step budget should absorb it; I have
   not measured it, and if the eval's n is far larger than the ~30 steps in this data the n^2 term
   grows and the budget claim weakens.
4. The objective swap is the one unmeasured genome element. If r22_exact_target_equivalence_quotient
   is worse than r4_dupclass_ring_negatives in this arch's context, that cost is charged against
   the head's gain and could hide it.
